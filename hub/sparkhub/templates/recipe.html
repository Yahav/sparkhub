Mods

sparkrun mods: scripts that patch the container (usually vLLM's own Python files) before the server starts, in this order. Each is pinned to the commit it had at import, and these files are exactly what runs: the hub stores them with the recipe and copies them into every new container. Your approval covers them. Mods that would download anything at launch are refused at import. After the download, the mods run once in a throwaway container with no network, so a mod that fails stops the recipe before it can be assigned.

Review checklist
  • Is the image pinned by digest (it is), and was it built by public CI or on the author's machine? See Image build.
  • For layers that add code: do the installed packages match public git commits? Diff the image's site-packages against the repo at the stated commit.
  • Precompiled caches in the image (torch AOT, Inductor, Triton) are pickles plus generated Python that load at startup. Scan the pickle globals (torch/triton/vllm only), and check the embedded sources match the image's files.
  • Model repo: no .py files, no auto_map, only safetensors (no .bin/.pt pickles). Checksums are verified at download.
  • Command prelude: what does it download, and from where (highlighted above)?
    • {% if d.mods %}
  • Mods: what does each one change in vLLM, and is it the upstream fix it says it is (its README or comments usually name a vLLM pull request)? A mod from another repository than the recipe deserves the same look.
    • {% endif %}
  • Environment flags the author calls experimental, and their effect on quality.
  • License of the weights.
